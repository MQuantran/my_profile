Autonomous Vehicle Navigation System

Control system for lane keeping, cruise control, and obstacle detection

Project Overview

Developed a modular control system for an autonomous vehicle to navigate closed circuits. The architecture integrated classical PID control with Reinforcement Learning (RL) to enhance performance in complex, noisy environments.

Impact

The system demonstrated a successful sim-to-real transition, overcoming challenges such as sensor noise and non-linear vehicle dynamics.

  • Robust Navigation: Consistently completed laps on a closed circuit without lane departures.
  • Efficiency: Residual RL integration optimized control parameters without exhaustive manual tuning.
  • Reliability: Integrated obstacle detection allowed for safe emergency stops during high-speed testing.

System Integration & FSM

To incorporate every sub-system effort, I implemented a Finite State Machine (FSM) that prioritized safety and mission objectives.

  • Detection State: Constantly monitors cone positions and obstacle distance using the integrated vision pipeline.
  • Navigation State: Executes lane-keeping and cruise control policies when the path is clear.
  • Evasive Maneuver State: Triggered by the object detection module to override standard navigation for collision avoidance.
  • Emergency Stop: A fail-safe state that engages maximum braking if an obstacle is unavoidable.

Core Engineering Modules

Lane Keeping & Curve Handling

Designed a steering policy using a baseline PID controller to follow road centerlines estimated from cone positions. Key improvements over a simple PID included:

  • DBSCAN Clustering: Replaced K-means with density-based clustering to accurately separate left and right lane cones, especially on curved sections where K-means struggled.
  • PCA Lane Direction: Applied Principal Component Analysis to the detected cone point cloud to estimate road heading, adding a heading-error term to the steering command for smoother cornering.
  • Adaptive Lane Geometry: Dynamically estimated road width per timestep so the controller could handle variable cone spacing without manual tuning.
  • Residual RL: Wrapped a Reinforcement Learning agent around the PID baseline - the RL policy learns a residual correction ∆u on top of the PID output, improving smoothness without requiring end-to-end training from scratch.

Cruise Control (My primary contribution)

Designed and implemented an ESC (Electronic Speed Controller) policy that maintains a target velocity while dynamically reducing speed through sharp curves to preserve traction and stability. Key design decisions:

  • Curvature-Aware Speed Reduction: The controller reads the estimated road curvature ahead and scales down the target velocity proportionally - sharper turns trigger earlier and deeper deceleration.
  • Battery Compensation: Addressed a real-hardware challenge where dropping battery voltage causes the integral term to over-correct; the policy was tuned to remain stable across the full battery charge range.
  • FSM Integration: The cruise controller operates as a state in the Finite State Machine - it hands off control authority to the evasive-maneuver or emergency-stop states when the object detection module raises an alert.

Object Detection

Implemented a vision pipeline to identify cones and obstacles on the track, triggering reactive evasive manoeuvres or emergency stops to prevent collisions.

What I Learned

This project provided deep insights into the practical challenges of robotic control systems:

  • Sim-to-Real Gap: Algorithms that worked perfectly in simulation (e.g., curvature-based feedforward steering) needed substantial re-tuning or validation on the real hardware due to sensor noise and uneven cone placement.
  • Hardware Constraints: Battery voltage drop introduced non-linear behavior in the ESC, making it essential to design control policies that remain stable across the full discharge range.
  • Algorithm Selection Matters: Switching from K-means to DBSCAN for cone clustering was a key insight - the geometry of lane boundaries simply doesn't fit spherical cluster assumptions, and choosing the right algorithm unlocked reliable cornering performance.
  • Hybrid Architectures: The Residual RL approach (RL corrects a PID baseline rather than learning from scratch) was far more practical - it required less training data, converged faster, and kept the system interpretable.
  • System Integration: Harmonizing independent sub-systems (lane keeping, cruise control, object detection) into a single state-driven FSM revealed subtle coupling effects that couldn't be caught by testing modules in isolation.
